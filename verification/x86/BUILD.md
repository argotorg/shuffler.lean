# Proof build

From the repository root:

```sh
nix build .#x86-proofs --no-link -L
```

The same derivation is exposed as `checks.x86-proofs`. It uses the pinned Rocq,
ArchSem, Sail, and LLVM proof dependencies. The package contains the checked
Rocq source and `.vo` files, the assembled `permute.o` and its code bytes, the
assumption reports, and the build logs.

`check.py` copies the proof sources into an empty output directory. It compiles
that copy in the order in `MODULES`. It rejects a source file omitted from the
list. Add a new proof file to this list after its dependencies.

The build checks every named lemma, theorem, corollary, proposition, fact,
remark, and example in those files. It calls the unchanged per-theorem checker
from `spikes/clight-permute/check-assumptions.py`. Selected public claims must
also be present. The build then runs `coqchk` independently on all modules.

`kernel-axioms.txt` records the imported context of the pinned dependencies
`ArchSemX86.X86Inst` and `FullContract`. This context contains upstream axioms
that the project theorems do not use. The per-theorem policy remains narrower.
The checker requires the same kernel context and rejects unsafe typing modes.
The baseline was obtained with:

```sh
coqchk -silent -o -R COMPCERT_PROOFS compcert -Q LLVM_PROOFS '' \
  ArchSemX86.X86Inst FullContract
```

`patches/archsem-adapter-module.patch` writes the Sail adapter instantiation as
`Module ... Include ... End`. Rocq 9.1.1 compiles the upstream module alias but
its independent checker fails on that alias with `ModuleTypingError`. The
included definitions pass both the ArchSem model tests and `coqchk`. The patch
does not change the adapter definitions.

The byte-export tests assemble the production `permute.S` and compare its
bytes with `X86Program.v`. They also check an instruction mutation, an object
with missing labels, and an object with unresolved relocations. `test_check.py`
checks the manifest and kernel-report failure cases.

`test_proofs.py` changes `mov eax, 2` to `mov eax, 3`, then separately changes
`cmp edi, 1025` to `cmp edi, 1024`. It assembles each changed program and exports
its actual bytes through `generate_program.py`. It compiles isolated proof
copies from source and requires rejection in `size_return_invalid_step` and
`decode_entry_control`, respectively. A failure before the expected decoding
proof does not count as success. The package retains the changed objects,
generated byte definitions, and compiler logs in `mutations/`.

For a local build inside `nix develop .#x86-equiv`, pass the installed dependency
proof directories and an empty output directory:

```sh
python3 verification/x86/check.py COMPCERT_PROOFS LLVM_PROOFS \
  spikes/clight-permute/check-assumptions.py OUTPUT
```

The output is separate from the source tree's compiled proof files. The scope
of the semantic results is given by the checked theorem statements; the build
package alone does not add an equivalence theorem.

`empty_call_run_agrees`, `oversized_call_run_agrees`, and
`nonempty_call_run_agrees` include the complete LLVM function call and machine
execution from ABI entry through RET. The nonempty theorem covers sizes from
1 through 1024 with a permutation destination map, 32-bit unsigned source
values, and six separate arrays of the required capacities. The finite memory
layout and call frame require address bounds and separation of buffers, code,
and stack. Scratch arrays need mapped writable storage but no initial values.

The LLVM and machine executions share one final CompCert memory witness. The
nonempty theorem relates that witness to the exact model result: data,
permutation, trace prefix, and the three output fields. It also preserves the
callee-saved registers and restores the stack pointer to its return value.
Machine execution uses `sail_tiny_x86_sem true`. Its `opModel.run` result has
exactly one final state and no errors. Neither execution is a theorem premise.

The prefix and loop theorems are intermediate steps in these call proofs.
`main_loop_from_exchange_agreements` has three branch-proof premises;
`main_loop_agrees` supplies them from the checked exchange proofs. The final
call theorems have no such branch-proof premises. Malformed destination arrays
are outside the nonempty theorem. The call results use the flat Sail model;
they do not establish a hardware or operating-system theorem or a
step-for-step bisimulation.
