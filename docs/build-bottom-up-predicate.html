Yes. The full “if and only if” is now proved in Lean.

The theorem buildBottomUp_succeeds_iff_static assumes only initial.Valid. It covers every stack size and both directions of the condition. Tests provide separate checks of the executable predicate. See the proof and its assumptions.

01

First, what is the question?

We want to decide whether buildBottomUp initial returns .ok or a blocked error. We want a condition that reads the initial state only.

“Necessary and sufficient” means both directions: if the condition holds, BBU succeeds; if BBU succeeds, the condition holds. A condition that only covers small stacks is useful, but it does not answer this question for every input.

The condition has three main checks:

01 / DEEP POSITIONS

The value is already right.

Where a swap cannot reach, the value must already equal the value required there.

02 / FUTURE COPIES

A needed copy stays in reach.

A value that must be duplicated must have a copy in the top 16 slots at each relevant prefix.

03 / THE END OF THE DEEP PART

The remaining work can finish.

Check either the last copy at the 17-slot boundary, or the remaining permutation.

We will define these checks from fixed lists, counts, and one fixed permutation. The predicate does not run a second version of BBU.

Assumption throughout: initial.Valid. The stack length plus the pending generation count equals the target length. The number of unassigned targets equals that count. Every target value is present somewhere, can be generated, or can be loaded. “Present somewhere” does not mean “within DUP reach”.
02

Two ways to name the same slot

A position counts from the bottom. Position 0 is the bottom slot. A depth counts from the top. Depth 0 is the top slot.

For a stack of length L, position i has depth L − 1 − i. In every horizontal stack below, the bottom is on the left and the top is on the right.

An 18-slot stack. The numbers above are positions. The numbers below are depths. The top itself needs no SWAP.

MAX_DUP_DEPTH = 15. Thus DUP can copy from 16 slots: depths 0 through 15.

MAX_SWAP_DEPTH = 16. Thus the top can exchange with positions at depths 1 through 16. This gives a 17-slot region, including the top.

This one-slot difference is the reason the final boundary check exists. A value at depth 16 can be moved with SWAP, but it cannot be copied with DUP.
03

An assignment is a promise about a target position

Write S for initial.stack, and T for target. Let n = S.length and m = T.length.

An assignment f(i) = j means: “the value in current stack slot i is assigned to target position j.” This assignment does not mean that the value is already at position j.

In this small example, x is a variable value, numbers are literal values, and * is a wildcard target.

Arrows are assignments, not stack operations. Green target slots already have an assigned source. Amber target slots need a new slot.

Let B be the initially assigned target positions. Let U be the initially unassigned target positions, in increasing order.

B = [0, 1, 3, 4]
U = [2, 5]Here n = 4, m = 6, and two target slots still need a new value.

Validity and the mapping’s one-to-one structure imply that every current stack slot has an assignment. Hence |B| = n and n + |U| = m.

S can differ from the function’s original source. The initial state can already contain a trace from source to S. The predicate reads S, the current stack at the start of this BBU call.
04

The target and the expected result are different objects

T is what the caller asks for. E = initial.expectedStack records the values fixed by the initial assignments.

  1. If target position j is assigned to source slot i, set E[j] = S[i].

  2. If target position j is unassigned, set E[j] = T[j].

The wildcard asks for no particular value. The assigned 7 is the value that BBU must preserve.

In the C++ mapping builder, a correct assignment permits:

T[j].is_junk ∨ S[i] = T[j]The target is a wildcard, or the assigned value equals the target value.

Thus a correct wildcard assignment need not satisfy literal equality with the target. We must use E in the static success condition. We can replace E with T only under the stronger assumption that every assigned value equals its target value.

Equality here compares the exact Value constructors. An assigned wildcard target can receive a concrete value such as 7. An unassigned wildcard stays Wildcard in E, because that is the value selected for generation.

There is already a Lean theorem that a successful BBU run from a valid state returns exactly E. Whether this result matches the caller’s target is a separate mapping question.

05

Build two fixed objects, once

First: the list A

Start with all values of S. Then append the target values at positions in U, in increasing target order.

A = S ++ [T[u₀], T[u₁], …, T[uₚ₋₁]]

A has length m. Its appended values are known from the input. This construction does not assert that BBU can produce them.

A is not a shadow stack. We never swap its entries, update it, or choose a next state. It is a fixed list of coordinates that we can inspect.

In the deep part of a successful run, values can stay in these coordinates because equal values let BBU exchange assignments without moving stack values. The predicate checks the conditions under which this description applies. It does not claim that A describes the stack after later swaps.

Second: the permutation π

Keep each original assignment. Assign the appended coordinate n+k to its original unassigned target uₖ.

π(i) = f(i), for i < n
π(n+k) = uₖEvery coordinate has one destination. Every destination has one coordinate.

The two amber arrows complete the original mapping. All arrows and cycles are fixed by the initial data.

A permutation splits into cycles. For example, coordinate 1 goes to 4, then 4 goes to 2, then 2 goes to 3, and 3 goes back to 1. We only need cycles if all new slots are produced before the deep part ends.

Keep these roles separate: A holds values by coordinate. E holds the required result by destination. π says which coordinate is assigned to which destination. In particular, A[i] = E[π(i)].
06

Use one larger example for the counts

We now use an 18-slot stack. The variable x cannot be generated or loaded. The literal 0 can be generated. The notation 0 × 14 means fourteen copies of zero.

S = [0, x, 0, x] ++ [0 × 14]            n = 18
U = [1, 3, 20]                          m = 21

initial destinations:
  source 0 → target 0
  source 1 → target 2
  source i → target i+2, for 2 ≤ i < 18

T = E = [0, x, x, 0, 0, x] ++ [0 × 14] ++ [x]
A     = [0, x, 0, x] ++ [0 × 14] ++ [x, 0, x]

The assigned target positions start with 0, 2, 4, 5, …. The three unassigned positions need values x, 0, x.

Let c mean a proposed completed prefix: target positions 0 through c−1 have been handled. We will inspect several values of c using the same input.

A quantifier such as for every c ≤ q asks for several independent checks on fixed data. It does not ask us to update a state and call the predicate again.
07

Count how much of A belongs to each prefix

g(c): how many unassigned targets are before c?

If the deep prefix has completed, each initially unassigned target before c has required one additional slot. Count those positions:

g(c) = |{u ∈ U : u < c}|

For our example, U = [1, 3, 20]. Therefore g(0)=0, g(1)=0, and g(2)=1. Position 1 counts only once the prefix extends past it.

L(c): how many coordinates are then included?

L(c) = n + g(c)

The first n coordinates are the original stack. The next g(c) coordinates are the values associated with the earlier unassigned targets. We inspect A[0 : L(c)].

C(c,v): how many copies of v are in its top 16 slots?

C(c,v) = count of v in A[max(0,L(c)−16) : L(c)]A slice [a : b] includes a and excludes b. If the prefix has fewer than 16 slots, inspect the whole prefix.

Green cells belong to the selected window. Purple cells are copies of x within that window. Dashed cells are later coordinates, which do not count yet.

08

R(c) asks whether each remaining value can still be made

Some values do not need DUP. A literal can be pushed. A spilled variable can be loaded. Write Free(v) for either case:

Free(v) ⇔ v can be freely generated or loaded from spills

“Free” here is a name for this predicate. It does not mean the operation has zero cost.

Now ask whether a future unassigned target still needs a particular value:

Need(c,v) ⇔ ¬Free(v) ∧
  ∃u ∈ U, c ≤ u ∧ T[u] = v

If Need(c,v) holds, we need a reachable copy of v. This gives the reachability check:

R(c) ⇔ ∀v, Need(c,v) → C(c,v) > 0

The same statement can be written directly over the unassigned targets:

R(c) ⇔ ∀u ∈ U, c ≤ u →
  Free(T[u]) ∨ C(c,T[u]) > 0

In the running example, x is needed at the later unassigned position 20. At c=0,1,2, the window has respectively 1, 1, and 2 copies. Thus all three checks pass.

Why check more than R(0)?

A new slot can push the last usable copy beyond depth 15. Initial reachability alone cannot exclude that failure.

Take S = [0,x] ++ [0 × 15] and unassigned targets U = [0,1]. They require 0, then x. Assign source position i to target i+2. The first target already agrees with the bottom zero.

This is a separate valid input. At c=0 a copy of x exists in the window. At c=1 it does not. BBU returns a blocked error for this input. If x is spilled, R(1) holds through the load alternative.

The predicate therefore checks R(c) for every relevant prefix, not only for the initial one.

Only unassigned targets create Need. An assigned target already owns a slot. Moving that slot can still fail because of SWAP depth; a later check handles that problem.
09

Find the end of the deep part without running the loop

Assume n > 16. The number of current stack slots at or above the next position is:

width(c) = L(c) − c

Completing an assigned target reduces this width by one. Completing an unassigned target adds a slot and completes a position, so the width stays the same.

This count is why we use the order of assigned target positions, rather than only the target length.

t: the assigned position at the 17-slot boundary

Let t be the (n−16)-th member of B, counting from one. Just before processing it, n−17 earlier assigned positions have been completed. The remaining width is 17.

In the running example, n=18. We need the second assigned target. Since B starts [0,2,…], we get t=2.

h: the point after all new slots are needed

If U is empty, let h=0. Otherwise set h=1+max U. At prefix h, every initially unassigned target lies below the prefix.

For the running example, t=2 and h=21. The ellipsis hides assigned positions 8 through 18. It does not hide another unassigned position.

q: stop at the first of these two points

q = min(t,h)

There are two endings:

  • If t < h: we reach 17 remaining slots while new slots are still needed. We check one possible loss of a copy.
  • If h ≤ t: all new slots are complete first. We check the remaining permutation. A tie belongs to this case.

In the running example, q=t=2. We only need to inspect prefixes 0, 1, and 2. We do not simulate the later part of the run.

10

Before q, a wrong value is too deep to replace

The first large-stack clause is:

∀c < q, A[c] = E[c]

This says that every position in the deep prefix already contains its required value. Its assignment does not have to be final yet.

  1. For an assigned target before q: at least 18 slots remain. An unequal value would need a final swap deeper than SWAP permits.

  2. For an unassigned target before q: at least 17 slots remain before generation. Generation adds one. An unequal value would then need an out-of-reach swap.

  3. If the values agree: BBU can exchange the destination assignments. The values stay in place. This is what lets one fixed list A describe this prefix.

Agreement is required before q. It is not required at q itself; the terminal condition handles that position.

The second large-stack clause is:

∀c ≤ q, R(c)

The bounds differ on purpose. Values must agree before the terminal position. Needed copies must be available through that position, including the point where the final check starts.

These clauses work together. The equality clause explains why the fixed coordinates remain valid for this part of the argument. The reachability clause prevents a required generation from failing within that prefix.
11

If t < h: protect the last copy at depth 16

At position t, exactly 17 current slots remain to process. The target at t is assigned. Set v = E[t], the value required there.

The boundary check is:

A[t] = v ∨ ¬Need(t,v) ∨ C(t,v) ≥ 2

At least one of these three alternatives must hold. Read them slowly:

  1. The value is already right: A[t]=v.
    Only the assignments need to change. No reachable copy is lost. After this position, at most 16 slots remain.

  2. A later DUP does not need this value: ¬Need(t,v).
    Perhaps no later unassigned target asks for it. Or perhaps the value can be generated or loaded. We may move the last reachable copy to depth 16.

  3. There are at least two reachable copies: C(t,v)≥2.
    We can put one at depth 16 and still leave one within DUP reach.

Here x is an unspilled variable, and the final unassigned target still needs x. Both inputs have U={17}, t=0 and h=18. The arrows show one boundary placement to explain the count; the static predicate itself updates no stack.

The one-copy example has S=[0,x] ++ [0 × 15]. The initial mapping exchanges the destinations of positions 0 and 1 and fixes positions 2 through 16. The target is [x] ++ [0 × 16] ++ [x].

At this boundary, R(0) is true: a copy exists. But the terminal condition is false: the bottom is unequal, the future target still needs x, and only one copy is in reach. BBU blocks.

Change a second zero to x and keep the mapping consistent with that value. Now the copy count is two, and BBU succeeds. Alternatively, put x in spills. A load then removes the need for a reachable copy, so the one-copy case succeeds.

Why is the unequal placement safe for every other value?

The required value is assigned somewhere in the unfinished region. Since it differs from the bottom, an assigned copy lies above that bottom, in the top 16 slots. BBU uses swaps to put it at depth 16.

This removes exactly one reachable copy of v. The former bottom value enters the reachable region. No other value loses a reachable copy. The old bottom value gains one. Thus only the remaining need for v requires a special check.

After that placement, only 16 slots remain to process. The existing Lean reachability theorem covers the rest.

12

If h ≤ t: only the permutation remains

At prefix h, all initially unassigned targets have been handled. The stack has its full length m. There are no more slots to generate.

BBU then uses Permute. For that function to succeed, every position below SWAP reach must already be fixed by the remaining mapping.

A position i is too deep when i < m−17.Natural-number subtraction is used: if m < 17, m−17 means 0.

We only need to inspect unfinished positions, so the relevant range is h ≤ i < m−17.

How can we inspect the remaining mapping without updating it?

Use the original fixed permutation π. Completing a deep position by an assignment exchange removes that position from its cycle and fixes it.

After the prefix below h is removed, position i is fixed exactly when it is the only position at or above h in its original cycle.

“Ignore” means intersect the original cycle with the fixed range {h,…,m−1}. The predicate does not construct a new mapping. In these pictures h=1.

Define the final permutation check:

P(c) ⇔ ∀i, c ≤ i < m−17 →
  Cycleπ(i) ∩ {c,…,m−1} = {i}

Then the terminal condition for this case is simply P(h). There is no restriction on cycles entirely within SWAP reach.

Why not just compare the final values?

The production Permute follows its permutation. Equal values do not cancel a nontrivial cycle for it. Consider these two inputs with all values equal to zero:

Both have n=18, m=19 and U={0}. Therefore t=2, h=1 and q=1. The prefix value test and every reachability test pass in both inputs.

13

Put the clauses together

We now have a single predicate on the initial data. It contains finite counts, finite quantifiers, and a cycle property of one fixed permutation.

This is the structure of the predicate, not an execution trace. No branch calls the predicate again.

If n ≤ 16

StaticSuccess ⇔ R(0)

For a valid state of this size, every present value is within DUP reach. Thus R(0) follows from validity. The existing small-stack theorem guarantees success. The target can be much longer than 16 slots.

If n > 16

Compute t, h, and q=min(t,h) as above. Then require:

(∀ c < q, A[c] = E[c])
∧
(∀ c ≤ q, R(c))
∧
(
  (h ≤ t ∧ P(h))
  ∨
  (t < h ∧
    (A[t] = E[t]
     ∨ ¬Need(t,E[t])
     ∨ C(t,E[t]) ≥ 2))
)

The proved equivalence is:

initial.Valid →
  (StaticSuccess initial ↔
    ∃ result, buildBottomUp initial = .ok result)
The full equivalence is proved in Lean.

buildBottomUp_succeeds_iff_static, at line 27, states the public result. The full proof connects the fixed prefix and both terminal cases to the production function. The proof assumes initial.Valid; it does not assume strict equality between assigned values and target values.

Why this does not need a shadow stack

  • A, E, U, B, and π are constructed once.
  • g(c), L(c), and C(c,v) are independent queries on those objects.
  • t and h come from the order of the original assigned and unassigned targets.
  • P(h) inspects the original cycles; it does not update the mapping.
  • The 17-slot test is one count and two alternatives, not a recursive run.

“Nonrecursive” does not mean “constant time”. A checker can use loops to count items or inspect a cycle. The point is that the mathematical condition does not invoke itself on a changed BBU state.

14

Read the complete checks from start to finish

Example A: the 17-slot boundary comes first

Return to the running example from step 6. The mapping is value-correct, so E=T.

  1. Find the cutoffs.
    n=18, U=[1,3,20], B=[0,2,4,…,19]. The second assigned target is 2, so t=2. The final unassigned target is 20, so h=21. Therefore q=2.

  2. Compare deep values.
    A[0]=E[0]=0 and A[1]=E[1]=x. These are the only positions strictly before q.

  3. Check the windows.
    The only value needing DUP is x. The counts at c=0,1,2 are 1,1,2. Thus R(0), R(1), and R(2) all hold.

  4. Check the boundary.
    t<h. The bottom value A[2]=0 differs from E[2]=x. A future target still needs x. But C(2,x)=2, so the two-copy alternative holds.

  5. The predicate is true. Production BBU succeeds.
    The later part of the run does not need to be simulated to evaluate this predicate.

Example B: all new slots are complete first

Take 18 zeros and a target of 19 zeros. The only unassigned target is 0. Assign source position i to target i+1.

  1. Find the cutoffs.
    U=[0], B=[1,…,18]. Thus t=2, h=1, and q=1.

  2. Check values and copies.
    A[0]=E[0]=0. Every unassigned target value is a literal, so each required R check holds.

  3. Check cycles.
    Since h≤t, inspect P(1). Here m−17=2, so position 1 must be fixed after the prefix is removed. Its original cycle is (0,1,…,18). Ignoring 0 leaves many positions in the cycle, not only 1.

  4. The predicate is false. Production BBU blocks.
    If the initial mapping instead fixes positions 1 through 17 and sends source 0 to target 18, the completed permutation has only cycle (0,18). Then P(1) holds and BBU succeeds.

Empty and boundary cases
  • Empty source and target: n=0, U is empty, and R(0) is true because there are no remaining needs. BBU succeeds.
  • Empty current stack, nonempty target: validity requires every target value to be generatable or loadable. Thus R(0) holds and the small-stack theorem applies.
  • No unassigned targets: U is empty and h=0. For n>16, q=0. The value-prefix check is empty, reachability is automatic, and the condition reduces to P(0): all positions outside SWAP reach are fixed by π.
  • Exactly 16 initial slots: use the small branch. Do not compute t.
  • Exactly 17 initial slots with a later unassigned target: t is the first assigned target. A prefix of equal-value unassigned targets may come before it.
  • h=t: use the permutation branch. At that point only 17 slots remain, so there are no unfinished positions below SWAP reach. P(h) has an empty range and is true.
15

What has actually been proved?

The entire static success condition is now proved necessary and sufficient in Lean. The proof applies to the production buildBottomUp function for every valid initial state.

theorem buildBottomUp_succeeds_iff_static
    (initial : State source target spills)
    (h : initial.Valid) :
  (∃ res trace, buildBottomUp initial = .ok ⟨res, trace⟩)
    ↔ StaticSuccess initial

Read the public theorem at line 27, the literal predicate definition, or the full equivalence proof.

The proof checks the fixed-coordinate description and the original-cycle description through the deep prefix. It then proves the final permutation case and the 17-slot copy case. The axiom audit lists only Lean’s standard propext, Classical.choice, and Quot.sound.

The predicate itself is executable. Its decision instances use finite checks of the literal initial-state formula. They do not call BBU or use a classical decision oracle.

Current production tests compare that literal predicate with BBU on 644 generated valid inputs: 408 successes, 236 blocked results, and zero disagreements. They also check 13 fixed valid inputs and one invalid availability input. These include both boundary copy cases, spills, a copy hidden by generation, deep cycles, wildcards, and mismatched concrete assignments.

The tests check the implementation of the predicate and selected examples. The Lean theorem supplies the universal result.

Does this also prove that the result equals the target?

Success from a valid state gives exactly E = expectedStack. The theorem buildBottomUp_correct_iff_static, at line 38, gives a trace to the exact target under this additional assumption:

∀ i j, initial.mapping i = some j →
  initial.stack[i] = target[j]

This is strict value equality. A wildcard target can accept an assigned concrete value under the C++ matching rule, but those two Value constructors are not equal. The success theorem uses E, so it does not need this stronger assumption. A general wildcard-aware target-matching theorem is a separate result.

Other public theorem names and assumptions
  • buildBottomUp_expected_of_ok: successful result equals E, assuming validity.
  • buildBottomUp_reachable_of_ok: success implies Reachable, assuming validity.
  • buildBottomUp_succeeds_of_processed: a final prefix plus WithinReach guarantees success.
  • buildBottomUp_succeeds_iff_reachable_of_processed: under validity, a final prefix, and at most 16 remaining current slots, success is equivalent to Reachable.
  • buildBottomUp_succeeds_small: validity plus at most 16 initial slots guarantees success.

Here “final prefix” is an assumption about the mapping: each position maps to itself. It is stronger than merely having the right value there.

The proof target is success, not an optimal trace. The predicate does not state that BBU uses the fewest operations, or that failure means no other algorithm could build a matching stack.
